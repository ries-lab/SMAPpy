# Architecture and UX review, October 2026

A whole-codebase review on `main` at f319794, written under the brief "a new
product nobody else uses: SMAP compatibility and backwards compatibility can
go; find what is complicated, what can be unified, what is unintuitive".
Nine reviewers read the code by area; one drove the real GUI offscreen
through simulate -> fit -> drift -> group/measure -> ROIs -> save and took
screenshots.  Every finding cites the code; the ones marked **(verified)**
were re-checked by hand.  Nothing here is changed yet -- this is the list to
decide from.

---

## 1. The short version

The algorithms are good and mostly lean (the C++ fitters, RCC, FRC,
simulate, ground truth, line-profile likelihoods).  The complexity is in the
**layers around them**, and it has one recurring shape: *two of everything*,
because a newer design was added beside an older one instead of replacing it.

| two of | where |
| --- | --- |
| two GUIs | the Qt app, and the matplotlib `Viewer`/`LiveViewer` behind `smappy-view` / `smappy-live` |
| two units | nm tables and pixel tables (`x_pix`, `xy_err_pix`), with fallbacks in 18 files |
| two tables per layer | ungrouped and grouped, each with its own filter, a `share=` protocol and `grouped_stale` |
| two region runners, two result stores | `ROIProject.evaluate` and `region_runs.evaluate_regions`; `ROIProject.tables` and `Session.id_regions` |
| two ways to declare settings | `param()` on the field, and `Plugin.params` + `main` |
| two COMET fits | spline (default) and the time-window fit that pulls in 2,400 lines of `_comet` |
| two copies of COMET | `src/smappy/_comet` (used) and `externaltools/Comet` (608 KB, unused) |
| two registration settings classes | `RegisterSettings` and `DualColorSettings`, different defaults for the same geometry |
| two undo stacks, two live paths, two "ROI"s | see below |

Removing the older half of each pair is the bulk of the simplification —
an estimated **5,000–6,000 lines** — and several of them are also the cause
of real bugs (sections 3 and 4).

On **UX**, the app is fast; the friction is wording, discoverability and
feedback: no way to open a TIFF the way a newcomer tries, no Stop button, no
"unsaved changes" prompt, errors shown as one clipped `ValueError:` line,
filters on by default that a user cannot see, and four words for "region".

## 2. CLAUDE.md: what to relax

CLAUDE.md is the most-edited file in the repository (39 of 163 commits),
because ~300 of its 606 lines are an API reference (Context, Result, the
table, axes, simulation) that changes with every feature.

**2.1 Shrink it to practice and traps.**  Keep: getting the checkout to run,
the test tiers, the GC/`singleShot` traps, the plugin-shape table, house
style, pages.  Move "The context", "The result", "The table", "What the
picture's axes are", "Simulated data" into `docs/plugin-architecture.md` and
the docstrings they paraphrase.

**2.2 Soften "if it disagrees with the code, stop and ask".**  Proposed:

> If a line here disagrees with the code, trust the code.  If the fix is
> factual (a renamed file, function or test), correct it in the same change
> and say so.  Stop and ask only when a line states a *rule or intention*
> that the code contradicts.

**2.3 Drop the exhaustive plugin lists in tests.**  `test_discovery.py:239`,
`test_workspace.py:54,61,92,180`, `test_file_plugins.py:206` make every new
plugin edit 2–4 test files, and they are exactly the rebase conflicts the
"Pull first" section warns about.  Replace with invariants: a minimum set
(`>=`), the seeding *rule* (Analysis/ minus Regions/, finders before
summaries), and round-trips derived from `Workspace.default()`.  Proposed:

> The discovery and workspace tests check that the shipped plugins are found
> and that the tabs seed by rule.  Adding a plugin needs no test edits unless
> it changes a rule.

**2.4 Delete `UNDOCUMENTED`.**  It is empty (`test_plugin_docs.py:18`); the
sentence about "a list that only shrinks" describes nothing.

**2.5 Relax the page rules where they do not pay.**  Keep page version ==
plugin version (one cheap assertion).  Make figures *recommended* for
loaders, savers and simple plugins; require *Differences from SMAP* only for
ported plugins; drop "checked on PubMed" where there is no method paper.

**2.6 Design rules that the simplifications below would retire**:
"a pixel-unit table has `x_pix`" and the `next((n for n in ("xy_err_nm",
"xy_err_pix")...))` idiom (§4.1); the grouped table "with its own filter"
and `grouped_stale` (§4.2); "a run that only measures is not logged" and
`changes_locs` True/False/None + `changes_locs_for` (§4.3);
`ROIProject.evaluations` "a renamed one is a second evaluation" and
`Session.id_regions` (§4.4); the `notice`/`notice_for` split (§4.3);
"Discovery parses with ast and never imports" as an absolute (§6).

**2.7 Stale statements to fix regardless.**  `blocks.py` is
`smappy/blocks.py`, not a plugin (lines 112, 161); the `externaltools/Comet`
pytest trap disappears with §5 (or add `testpaths = ["tests"]`).  Outside
CLAUDE.md: `GUI.md:239-259` shows the old `run(locs, selection, ...)`
contract, its "Next steps" are mostly done, and it describes a favourites
star that no longer exists; `docs/regions.md:9` says "Nothing here is built
yet" **(verified)**; NOTES.md:858 and THIRD_PARTY_NOTICES point COMET at
`externaltools/`; `plugins/roi.py:1-19` still describes "Evaluate" plugins
and `ctx.site_table`; `docs/roi_manager.md` advertises the sidecar save.

## 3. Bugs found on the way (fix first, small)

1. **Regions tab stays at "0 ROIs" after the NPC Analysis chain** **(verified)**.
   `session.py:1600-1601` loads `roi_project` without `self.changed("rois")`
   (the `id_regions` and `rois` branches do emit it).
2. **Progress lines leave fragments in the output box** — "frame 200 of
   2,000 … 0 frame frame 600".  `plugin_panel.py:620-624` replaces
   `LineUnderCursor`, which is one *visual* line of a wrapped paragraph;
   select the block instead **(verified)**.
3. **One filter, two meanings** **(verified)**.  `Layer.set_bound`
   (`session.py:157`) writes the same bound to the grouped and ungrouped
   tables, but on the grouped table `xy_err_nm` is the combined precision
   and `photons` the sum.  With the default `xy_err_nm ≤ 25`, what is drawn
   (grouped) and what a plugin measures (ungrouped) silently differ.
4. **Grouping a pixel table links within 50 *pixels*** **(verified)**.
   `GroupSettings` uses "the units of the table" (`group.py:620,718`), and
   `pipeline.FitSettings.output_unit` defaults to `"pixel"`
   (`pipeline.py:40`) while the GUI and `api.fit` default to nm, and
   `smappy-fit` to pixel, `smappy-live` to nm.
5. **The COMET "torch" backend cannot work** **(verified)**: it imports
   `_comet/core/pytorch_wrapper`, which is not in the tree.
6. **The Gaussian 2D 2C preflight offers "start anyway", which always
   raises** (`fit.py:1412-1417` -> `1251-1257`).
7. **Statistics prints "(grouped)" twice** (`statistics.py:741`).
8. **Selecting a file in a fitter turns the file's camera values into "your
   settings"** **(verified, `fit.py:579-594`)**: a later camera choice is
   overridden by them, the next file inherits the previous file's values,
   and Camera parameters labels them "user: your setting".  `hints` already
   shows the auto values in grey; drop that branch of `react`.
9. **`Selection.require` warns through `progress`**, so the next progress
   line overwrites the "thin selection" warning — the failure `ctx.warn`
   exists to prevent (`plugins/__init__.py:257-266`).
10. **ROI numbers shift when an earlier ROI is deleted**: `numbers()` counts
    by creation order (`link.py:324`) **(verified)**, so a written `roi_id`
    column and "ROI 5" in the list can disagree.  Results rows use a uuid
    for `roi_id`, the localizations an integer.

## 4. Architecture: the big simplifications

Ranked by what they buy.  Effort is rough.

### 4.1 nm only (removes a unit system; fixes bug 4)
The fitter works in pixels internally and converts at the end; make that
conversion unconditional and drop `output_unit` / `units` ("nm / pixel /
pixel+nm"), `keep_pixels`, `_PIXEL_COLUMNS`/`to_nm` in `locs.py:171-260`,
the eleven `*_pix` rules in `group.py`, `xpix`/`ypix`/`PSFxpix` in
`SML_COLUMNS`, and every `xy_err_pix` fallback (81 hits, 18 files).  Only
registration needs chip pixels; it divides by the pixel size or keeps
`peak_x_pix`.  One `Localizations.first_of(*names)` replaces the five
precision-lookup helpers.  *~2 days, low risk.*

### 4.2 One grouped table per session, one filter per layer (fixes bug 3)
Today each layer's `ViewState` holds `{"ungrouped","grouped"}` sets with
their own `LocFilter`s, synchronised by `share=` in 10 call sites,
`_grouped_carries_the_filter`, bound copying in `rebind` /
`set_group_settings` / `add_layer` / `scratch`, a `grouped_stale` flag read
in 11 places, a per-layer `group_settings` that `set_group_settings`
overwrites on all layers anyway, and a third copy in the ROI manager keyed
by a digest.  Instead: `Session.grouped()` caches one grouped table keyed by
`(table id, settings)` and rebuilds on mismatch (no stale flag); a layer has
`grouped: bool` and **one** bounds dict, applied per localization, with the
grouped mask derived through `group_id`.

Also: **link lazily**.  Every file is linked on open (`GROUPED_BY_DEFAULT`,
`session.py:315-321`), which is why `_group_chunked.py` (362 lines, "not
exact") and the hidden `link_chunks` setting exist; link when a layer is
first switched to grouped, with progress, and the chunking can go or move
to C++.  *~3–4 days, medium risk (live fit, undo).*

### 4.3 The plugin contract: fewer hooks, typed effects
A plugin can declare 16 attributes and 15 hooks; many have one user.
- **Remove dead ones**: `Plugin.grouping` (no shipped user, threaded through
  chain/batch/session), `__smappy_plugins__`, `Context.site_table`,
  `ParamInfo.step`, `_hint_from_text` (require Python 3.10), the "base name
  ends in Plugin" heuristic, the favourites star (`widgets.py:89-95`).
- **One way to declare settings**: `param()` on `DriftSettings`,
  `RCCSettings`, `FitSettings`; delete `Plugin.params`, `main` and the
  dotted-`extra` merge.  The drift plugins' labels currently live in a
  different file from their fields.
- **One form-state hook**: `hints`, `active`, `choices`, `notice`,
  `notice_for` -> `describe(ctx, settings) -> FormState`.  Chains forward one
  hook instead of four (and today forget `notice`).
- **One effect hook**: `changes_locs` + `changes_locs_for` +
  `live_recipe_for` -> `effect(settings) -> none | table | recipe`, required,
  with no "None, ask after the run" path.
- **Typed effects instead of `Result.data` magic keys**: `Session.apply`
  dispatches on nine strings (`bounds`, `layers`, `roi_project`,
  `id_regions`, `rois`, `live_recipe`, `images`, `append`, `path`;
  `session.py:1509-1614`); a typo does nothing, and bug 1 lives here.  Make
  them `Result` fields or `Effect` objects.
- **Log every run**, measurements included.  Users look in History for
  "which settings did that FRC use?" and find nothing; then `logged`, and
  the separate measurement record in `remember`, go.
- **Rename the overloaded "live"**: `Plugin.live` -> `follows_roi` ("follow
  ROI"), `LiveRecipe` -> `ColumnRecipe`; "live" then means only a fit still
  appending.
- **Split `Context`** (17 arguments): `ctx.region: RegionRun | None`,
  `ctx.control` (stop, writer_finished).
*~4 days in all, low risk, mostly mechanical.*

### 4.4 Regions: one runner, one store, one vocabulary
- **One runner**: a `RegionSource` (`ids`, `tables`, `region`,
  `signature`) implemented for ROIs and for an id column; `BlockPlugin`'s
  three paths, `ROIProject.evaluate` and the fourth loop in `estimate` become
  one.
- **One store**: `session.region_tables[(source, label)]`; *results from*
  becomes a list of pairs instead of parsing `"per cluster_id: label"`.
- **An evaluation is its label.**  Today `entries()` treats a renamed step
  as the same measurement and `evaluations()` as a different one, with nine
  query methods, `AmbiguousEvaluation` and a "which evaluation?" preflight
  around it.
- **The ROI project holds a `chain.Block`**, not `Instance` lists + its own
  `Step` + converters (`roi_manager/pipeline.py`).
- **Remove**: the standalone file-backed `ROIProject` (`Source`,
  `add_file`, sidecar save/load, own `ViewState`; ~400 lines, no GUI user),
  the `reviewed` flag (never exposed), figure keeping (`keep_figures`,
  `Step.keep`; re-running one region costs milliseconds), `slow` /
  `fast_values` / `without_slow` (machinery for one checkbox), the SMAP
  method of NPC Labeling Efficiency, `absorb_run` and the fingerprint fudge.
- **One write-back**: *write values* in a block and *Regions to column* are
  the same operation with different overlap rules (4 vs 3) and a silent
  `any`->`last`; keep one.
- **Segmenters always replace their own earlier ROIs** on that file; undo
  covers regret.  Today a second NPC run finds "0 pores of 0 candidates"
  because the first run's ROIs suppress everything.
- **Grouping is decided at four levels** (layer, chain, step,
  `Plugin.grouping`): keep the layer (set by Chain/Layers in a chain).
- Rename `smappy/roi.py` (the fitter's boxes) to `fit_rois.py`.
*~5 days, medium risk; `test_roi_staleness`/`test_roi_pipeline` pin
behaviour that will change on purpose.*

### 4.5 Render threads take snapshots (the root of the GC workaround)
The 2D worker is handed the `RenderView` widget and walks the live
session's layers from its thread (`render_view.py:80`); the 3D worker is
handed the `Session` (`view3d.py:70`, "the table changed under us")
**(verified)**.  A widget referenced from a worker thread is how a Qt
object ends up destroyed off the GUI thread — the deadlock that turned
automatic GC off.  Take a frozen per-layer snapshot (arrays, mask,
settings) on the GUI thread and render that in a module-level function;
merge `_Renderer`/`_Renderer3D`, and `composite` into `panel_images`.  Keep
the collector as a safety net.  *~1 day, medium risk.*

### 4.6 Settings of the picture belong to the session
`RenderAxes` and `white_background` live on every layer, so
`Session.axes()` reads "the first locs layer" and `set_axes` writes all of
them.  A `PictureSettings` on the session.  The **slab** becomes a 3D ROI
("use as ROI" in the 3D window) instead of "plugins use the slab (while
open)" + `slab_follows_roi` + "from ROI": what a plugin measures should not
depend on whether a window is open.

### 4.7 Fitting
- **One Fit plugin** with `model: gaussian | spline`; channels from the
  calibration file (which already records one or two).  The four settings
  classes are the same six parts.  Every fitter gets the same *after the
  fit* part (today drift and colour assignment exist only on the 2C ones,
  with *assign colours* on by default).
- **One registration geometry**: `RegisterSettings` vs `DualColorSettings`
  differ in `min_pairs` (20/8), thresholds, and `layout` (`auto` vs a fixed
  `up-down mirrored` that fails on a left-right splitter).
- **One camera path**: database + typed fields.  Remove YAML presets (the
  *preset* dropdown beside *camera*), `io/cameras_mat.py` (263 lines), the
  three copies of the preset merge, and the five camera-resolution
  functions -> one `resolve(camera, source)`.
- Load the dual calibration once per run, not 3–4 times
  (`fit.py:1057-1085`); make `max_block_rois` (SMAP's area scaling),
  threads and iterations non-GUI; replace `api.fit`'s cutoff that changes
  meaning at 20.

### 4.8 Drift
Keep COMET's spline fit only; move its two kernels into `drift.py` and
delete the rest of `_comet` (2,436 lines, driven by overwriting module
globals at run time — not thread-safe) and 13 "time-window fit only"
settings, plus `two_stage` (the RCC prepass does that job).  Then one
*Drift correction* plugin with `method: COMET | RCC | RCC then COMET`.
Drift's own *group blinks / radius / gap* should default to the session's
link settings.  *Loses GPU drift (only the time-window path had it).*

### 4.9 Remove the second GUI and the second live path
`viewer.Viewer` and `live.LiveViewer` (matplotlib), `smappy-view`,
`smappy-live`: ~1,100 lines and ~40 tests, duplicating the Qt app and
`gui/live_session.py`.  Keep `LocSet`/`ViewState` (move to
`layer_state.py`), `LiveFit` and `camera_extent`.  With them go
`DisplaySettings.color_mode` ("sum"), `imax`, the public `weight_field`,
and NOTES "Interaction latency".

## 6. Keep (justified)

The C++ fitters (one per model, no duplication); whole-table undo on shared
arrays (only the OS memory probing could become a fixed cap); the live-fit
context pinning (fixes a real race); `Region` as the one shape; the batch
runner; uiPSF in its own process; the camera database with sources;
`simulate/`; `frc.py`; `rcc.py`; `RenderAxes` (sound design — trim only
the z axis in versatile mode and the separate *sigma y*); the GPU splat
engine for 3D (measured 10× faster); the GC collector and `singleShot`
rule (as a safety net after §4.5); the two test tiers; tutorials as
storyboards; `test_changes_locs`/`test_control_width` (they iterate, no
per-plugin edits).  AST discovery is defensible (a broken user plugin
cannot crash startup), but no shipped plugin imports anything heavy at top
level, so "import inside try/except" would also do — not urgent either way.

## 7. User experience

### 7.1 The workflow a newcomer meets
1. **Opening a TIFF**: File > Open lists only localization formats; File >
   Open image… shows a TIFF as an image layer; there is no drag-and-drop on
   either main window **(verified)**.  -> Open accepts `.tif` / OME / NDTiff
   and puts it in the fitter's *file*; drop on both windows.
2. **Empty start**: a black render window, "pixel 0.01 nm", "layer 1: 0".
   -> a hint on the empty view ("Open or drop a file — or File > Simulate"),
   and Help > Tutorials / "Try with simulated data" (the Help menu has
   neither).
3. **No Stop button** for a running fit or plugin **(verified)**; `ctx.stop`
   is honoured by the fitter and COMET but only MicroClaw sets it.  -> Run
   becomes Stop while running.
4. **No unsaved-changes prompt**, no dirty flag, no `*` in the title
   **(verified)**; first Save gives no confirmation and the title does not
   show the file.
5. **Errors**: a failed run is one clipped line "ValueError: …" under the
   fold, traceback to stdout; a failed load is a modal.  -> red status by
   Run, message without the class name, "details…" with the traceback and a
   bug-report button, the same for loads.
6. **Hidden default filters**: a new table opens with `xy_err_nm ≤ 25`,
   `logl_rel ≥ -2`, `|z| ≤ 500`; after a clean simulated fit they hide 33%,
   and the only cues are a "●" and "7,646 of 11,385".  -> active bounds as
   removable chips, "filters hide 33%" in the status bar.
7. **Hand-offs**: simulating camera frames says "open it in a fitter as its
   file" — the user retypes the path.  -> pre-fill or a "Fit this" button.
8. **Ctrl+Z means different things** in the ROI manager and the main window;
   name the target ("Undo RCC", "Undo ROI edit").
9. **The live-fit modal** appears only after pressing Run; grey out Run with
   a tooltip, keep "Run in a new window" as a visible secondary button.

### 7.2 Layout
- **Analysis tab**: 12 sections, alphabetical, no group headers, only one
  open at a time (`plugin_tab.py:194`).  -> group headers from the path,
  workflow order (Drift, Precision, Statistics, Line Profile, Remove, Math),
  `favorite=False` on History, Image Tags, Ground Truth, Calibrate
  transform; allow several open.
- **Localize tab**: fitters first, calibrations after.
- **Regions tab**: the header (ROI manager button, geometry, evaluate, a
  fixed-height results table) takes half the column and pushes Run buttons
  below the fold.  -> one collapsible section.
- **Too many entry points**: Open/Save in the File menu *and* as File-tab
  plugins (plus four per-format loaders that duplicate *Auto* -> one Load
  with an advanced *format*); Bead calibration in Tools and Localize (and it
  asks single/dual twice); ROI manager in Tools and Regions; Region steps in
  three places; "+ chain" on every tab.
- **About 15 top-level window types**; the 3D view alone adds two.  Dock the
  slab panel into the 3D window; give the render window a File menu.
- **Arranging a tab is right-click only**: a visible "⋯" on section headers.
- **Run panel**: Plot and Text duplicate what opens by itself and the output
  box; one "Show result".  Yes/no preflights default to No (Enter cancels
  the run the user asked for).  Every notice is orange bold, information
  included.

### 7.3 Forms
- **Gaussian 2D shows ~20 fields** before "more"; a user changes *file* and
  maybe *cutoff*.  Collapse camera to one line ("camera: auto — iXon 888,
  0.2 e⁻/ADU [edit]"); make *preset*, *units*, *show image tags*
  ("PIZStage") advanced or gone.  *cutoff value* keeps its number when
  *cutoff* switches between "× noise" and photons.
- **The 2C fit shows ~13 registration fields labelled by their Python
  names** (`vote_bin_px`, …), not collapsed.
- **`active()` exists but two plugins use it**: COMET shows *window size*
  first, which the default spline fit ignores; Assign colours shows its
  probabilistic-only settings for every method.
- **Settings that do nothing**: Statistics' *bins* (the fits ignore it),
  Precision's *bins*, Assign colours' plot LUT as an analysis setting;
  `precision_fit` + `fit_precision` are one choice.
- **Controls**: optional bools are tri-state boxes whose "auto" looks like a
  grey square (RCC *correct z*); floats are free text with no validation
  until Run; free-text fields for what should be combos (*for each*, *write
  back*, Column to ROIs' *column*).
- **"localizations" means something different in every plugin**: *as
  plotted / all*, *each visible layer / the selection*, *the drawn ROI / the
  selection*, or no choice.  One vocabulary: *selection / per layer / all*.
- **Line Profile** needs a line ROI, chosen by right-clicking the toolbar's
  ROI button: put a "Draw line" button in the panel.

### 7.4 Results
- **Histograms (region summary)**: 12 panels in one column, overlapping
  tick labels, no titles, all-NaN panels drawn (screenshot e13).  Grid of
  3–4 columns, a title each, skip empty.
- **Figure tabs are called "figure"**; RCC's result has no title or note.
- **No colour bar** when colouring by a column.
- **Line Profile**: no units, degenerate fits printed ("radius 0.0 ±
  419.4"), the winning model drawn under the others.
- **Region steps** after a run shows "167 ROIs, 1 step(s)" and no numbers;
  the ROI manager table shows no measured values; its ROI pane is black
  until a row is clicked.
- **Selecting an ROI silently computes and stores results** (*re-evaluate
  when out of date* on, *plot* off).

## 8. A proposed order

1. **Bugs** (§3) and **pure deletions** (§5): a day, no design questions.
2. **Quick UX wins**: Stop, unsaved prompt, open/drop TIFF, error display,
   filter chips, empty-state hint, Workspace menu, render-mode labels,
   Analysis group headers, Histograms grid.  ~3 days.
3. **nm only** (§4.1) and **remove the second GUI** (§4.9).
4. **Plugin contract** (§4.3) — makes everything after it cheaper.
5. **Grouping** (§4.2) and **render snapshots** (§4.5).
6. **Regions** (§4.4), **fitting** (§4.7), **drift** (§4.8), **picture
   settings / slab** (§4.6).
7. **CLAUDE.md** trimmed to match (§2) as each lands.

## 9. Decisions only the owner can make

- Keep reading SMAP `_sml.mat` localizations?  (Reviewers lean yes: the
  lab's data.)  Keep reading SMAP `_3dcal.mat` calibrations?  (Removing it
